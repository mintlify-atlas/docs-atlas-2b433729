Friday Night Funkin' (FNF) is an open-source rhythm game originally built for [Ludum Dare 47](https://ldjam.com/events/ludum-dare/47) and released on [Newgrounds](https://www.newgrounds.com/portal/view/770371). It is written in [Haxe](https://haxe.org) using the [HaxeFlixel](https://haxeflixel.com) game framework, and is developed and maintained by [The Funkin' Crew](https://github.com/FunkinCrew). Since its Newgrounds debut the game has grown into a fully-featured, moddable experience available on Windows, macOS, Linux, Android, iOS, and the web.

## What Is Friday Night Funkin'?

FNF is a single-player rhythm game in which the player must hit notes in time to the beat to win rap battles across a series of weeks. Beneath its approachable premise lies a rich technical foundation: a macro-powered scripting system, a built-in chart editor, a Polymod-based mod loader, and a multi-platform build pipeline that can target everything from a high-end desktop PC to a mobile browser.

The game was made with love for Newgrounds and its community, with extra love to Tom Fulp.

## Key Features

- **Polymod Mod Loader** — Drop-in mods are supported through [Polymod](https://github.com/FunkinCrew/polymod), allowing community members to add songs, characters, stages, and UI skins without touching the base game's source code.
- **Built-in Chart Editor** — A full-featured chart editor ships inside the game's Debug menu, letting creators author and preview charts without any external tools.
- **Scripted Classes** — The engine exposes a scripting API so mod authors can override or extend game logic entirely in Haxe scripts, without recompiling the game.
- **Multi-Platform Support** — A single codebase compiles for Windows, macOS, Linux, Android, iOS, and HTML5 via OpenFL and Lime.
- **HaxeUI Editor Tooling** — The stage editor and other UI tools are powered by [haxeui-core](https://github.com/FunkinCrew/haxeui-core), giving a native look and feel across platforms.

## Repository Layout

```
funkin/
├── source/          # All Haxe source code (game logic, UI, editors)
├── assets/          # Git submodule — proprietary game assets (sprites, audio, data)
├── docs/            # Compiling guides, troubleshooting, contributing docs
├── example_mods/    # Reference mod projects for the community
├── tools/           # Build and release tooling scripts
├── scripts/         # Pre/post-build Haxe scripts (Prebuild.hx, Postbuild.hx, converters)
├── templates/       # Platform-specific project templates
├── build/           # Build configuration and CI scripts (Dockerfile)
└── project.hxp      # Haxe project file (replaces project.xml)
```

<Warning>
  The `assets/` directory is a Git submodule that contains copyrighted game content. By cloning it you agree to the terms in the [funkin.assets LICENSE](https://github.com/FunkinCrew/funkin.assets/blob/main/LICENSE.md). Do **not** redistribute these assets.
</Warning>

## Key Dependencies

The game's full dependency list is managed by [hmm](https://github.com/FunkinCrew/hmm) and declared in `hmm.json`. The most important libraries are listed below.

| Library | Source | Purpose |
|---|---|---|
| `flixel` | FunkinCrew fork | HaxeFlixel — 2-D game framework |
| `openfl` | FunkinCrew fork | OpenFL — cross-platform Flash-API layer |
| `lime` | FunkinCrew fork | Low-level platform abstraction (audio, windowing, input) |
| `polymod` | FunkinCrew fork | Mod loading and asset patching |
| `haxeui-core` | FunkinCrew fork | UI component framework (editors) |
| `hxcpp` | FunkinCrew fork | C++ backend for native targets |
| `json2object` | FunkinCrew fork | Compile-time JSON serialisation/deserialisation |
| `hxvlc` | Haxelib 2.3.0 | Video playback via libVLC |
| `hxdiscord_rpc` | Haxelib 1.3.0 | Discord Rich Presence integration |
| `flixel-addons` | FunkinCrew fork | Extra HaxeFlixel utilities |
| `funkin.vis` | FunkinCrew fork | Audio visualisation helpers |
| `haxeui-flixel` | haxeui org | HaxeUI backend for HaxeFlixel |

<Note>
  FNF uses **forked versions** of many upstream libraries to ship patches not yet merged upstream. Always install dependencies through `hmm install` rather than `haxelib install` directly, or you may get incompatible versions.
</Note>
